# 附錄:第一次開源貢獻實戰 —— 從讀碼發現 bug 到上游 issue/PR

> 這章和前六章不同:不是「理解 WrenAI」,是「用你已經做到的事,完成第一次
> 開源貢獻」。素材就是第 1 章 §1.2 抓到的 guided 模板 bug——它是理想的
> 第一次:證據明確、影響真實、修法一行、不需要跟維護者辯論設計。
>
> 補充說明(為什麼加這章):這個專案的方法論是「以原始碼為準」,而開源貢獻
> 正是這個方法論的自然出口——你讀碼讀到能發現上游自己沒發現的 bug,
> 就已經具備貢獻者的全部前置技能,缺的只是流程知識。這章補流程。

---

## A.0 先懂遊戲規則:issue 和 PR 是兩件事

第一次貢獻最常見的困惑,先講清楚:

| | Issue(問題回報) | Pull Request(修正提交) |
|---|---|---|
| 是什麼 | 「我發現一個問題」的正式紀錄 | 「我把它修好了,請合併」的程式碼提交 |
| 門檻 | 低:會寫清楚的重現步驟就行 | 高一點:要 fork、改碼、過測試、走流程 |
| 一定要先有 issue 嗎 | — | 小修不強制,但**先開 issue 是禮貌**:讓維護者有機會說「這其實是故意的」或「我們正想改成別的」,你才不會白做工 |

我們的路線:**先開 issue(A.3),再視情況追加一行修正的 PR(A.4)**。
就算只做到 issue,也已經是有效貢獻——維護者自己修往往比你走完 PR 流程快,
而「發現並清楚回報」的功勞是你的。

## A.1 重現 bug(已在本機驗證過,照抄即可)

### bug 是什麼(30 秒版)

`wren ask "<問題>" --guided` 會印一份「一字一句照做」的任務流 prompt 給
LLM agent。它的第 2 步教 agent 跑:

```
wren memory recall --nl "<keywords>"
```

但 `recall` 指令根本沒有 `--nl` 這個選項(只收 `--query/-q`);
`--nl` 是 `memory store` 的參數。照著模板做的 agent 會直接吃
unknown-option 錯誤。

### 原始碼證據(三行定案)

```bash
cd /home/kasm-user/Desktop/wrenai101/.wrenai-src

# 1. 模板教的指令(錯誤來源)
grep -n "recall" core/wren/src/wren/ask_templates/guided.md.tmpl
#    6:  2. wren memory recall --nl "<keywords>"

# 2. recall 實際的參數定義:只有 --query/-q
sed -n '399,404p' core/wren/src/wren/memory/cli.py
#    query: Annotated[str, typer.Option("--query", "-q", ...)]

# 3. --nl 屬於誰:是 store 的參數
grep -n '"--nl"' core/wren/src/wren/memory/cli.py
#    354:    nl: Annotated[str, typer.Option("--nl", ...)]   ← 在 store() 裡
```

順帶查血統(寫 issue 時有用):`git log --oneline -- core/wren/src/wren/ask_templates/guided.md.tmpl`
→ 模板出自 `cbd10cd`(#2329)。另外對照:`wren context init` 產生的
AGENTS.md 模板(`context.py`)寫的是**正確的** `wren memory recall -q`——
所以這確定是筆誤,不是曾經存在過的舊介面。

### 對正式發布版重現(不是只對 git clone)

對「使用者實際裝到的東西」重現,issue 說服力完全不同。
本機已驗證(2026-07-09):

```bash
# 這台機器系統 Python 是 3.10,wrenai 要求 >=3.11 → 用 uv 起 3.12 venv
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
cd /tmp && uv venv --python 3.12 wren-repro
uv pip install --python /tmp/wren-repro/bin/python wrenai
/tmp/wren-repro/bin/wren --version        # → wrenai 0.12.0(PyPI 最新版)

# 重現一:模板真的教錯
/tmp/wren-repro/bin/wren ask "top customers by revenue?" --guided | head -8
#   ... 2. wren memory recall --nl "<keywords>" ...   ← 錯誤指令在輸出裡

# 重現二:照做真的會炸
/tmp/wren-repro/bin/wren memory recall --nl "top customers"
#   ╭─ Error ─────────────────────────────────────╮
#   │ No such option: --nl (Possible options: --help)
#   ╰─────────────────────────────────────────────╯

# 對照:正確 flag 能通過參數解析(卡在沒有專案,是預期行為,證明 flag 對了)
/tmp/wren-repro/bin/wren memory recall -q "top customers"
#   Error: no wren project found. ...
```

**教學點**:重現二 + 對照組是 issue 的靈魂。「錯誤 flag 炸、正確 flag 過」
這組對照讓維護者 10 秒內確認問題,不用自己想像。

## A.2 開 issue 前的兩個必做檢查(已替你做完,但流程要會)

1. **查重複**:`https://github.com/Canner/WrenAI/issues` 搜 `recall --nl`、
   `guided template`。(已查:0 筆相關,#2439/#2399 是無關的 memory 功能 issue。)
   重複回報是新手最常見的失禮,搜過再開。
2. **讀 CONTRIBUTING.md**:每個 repo 規矩不同。WrenAI 的重點:
   - bug 先搜既有 issues(✅ 做了);
   - commit 訊息用 conventional commits(`fix:`、`docs:`…)——PR 階段用得到;
   - `core/wren` 模組用 `uv` + `just install && just test`,lint 用 `ruff`。
   - 註:它的 bug report 模板是為 legacy Docker 版寫的(要 docker logs)——
     對 CLI bug 不適用,**照模板精神填、不適用的欄位改寫**即可,不用硬塞。

## A.3 Issue 草稿(直接可貼)

到 `https://github.com/Canner/WrenAI/issues/new?labels=bug` 貼上。
(用英文——上游是英文社群;標題格式模仿他們自己的 commit 風格。)

**Title:**

```
bug(wren): guided ask template instructs `wren memory recall --nl`, but recall only accepts `--query/-q`
```

**Body:**

~~~markdown
**Describe the bug**

The bundled guided ask template tells the agent to run
`wren memory recall --nl "<keywords>"`, but the `recall` command has no
`--nl` option — it only accepts `--query`/`-q`. (`--nl` belongs to
`wren memory store`.) An agent that follows the guided flow literally
gets an unknown-option error at step 2.

- Template: `core/wren/src/wren/ask_templates/guided.md.tmpl` line 6
  (introduced in #2329)
- Actual CLI signature: `core/wren/src/wren/memory/cli.py` — `recall()`
  defines only `--query/-q`; `--nl` is defined on `store()`
- For reference, the AGENTS.md template generated by `wren context init`
  uses the correct form (`wren memory recall -q ...`), so this looks like
  a typo in the guided template rather than an old interface.

**To Reproduce**

```bash
pip install wrenai   # reproduced on wrenai 0.12.0 (PyPI), Python 3.12

# 1. The guided template emits the broken command:
wren ask "top customers by revenue?" --guided | head -8
#   2. wren memory recall --nl "<keywords>"   # similar past queries ...

# 2. Following it fails:
wren memory recall --nl "top customers"
#   Error: No such option: --nl (Possible options: --help)

# 3. Control — the correct flag parses fine:
wren memory recall -q "top customers"
#   (proceeds past argument parsing)
```

**Expected behavior**

The guided template should instruct `wren memory recall -q "<keywords>"`
so that weaker LLMs following it verbatim (the template's stated audience)
don't hit an error.

**Wren AI Information**

- wrenai 0.12.0 (PyPI), also present on `main` @ a8a7519
- OS: Linux; Python 3.12

**Additional context**

One-line fix in `guided.md.tmpl` (`--nl` → `-q`). Happy to open a PR if
useful.
~~~

**教學點(這份草稿的解剖)**:
- **一句話講完 bug** 開頭,細節後置——維護者掃 issue 像你掃 log。
- **檔案路徑 + 行號 + 引入的 PR 編號**:替維護者做完 blame,這是讀碼型
  回報者最大的加值。
- **版本明確**(PyPI 0.12.0 + main HEAD):排除「舊版已修」的來回。
- **對照組**(正確 flag 能過):證明你懂正確行為,不是誤用。
- 結尾 **「Happy to open a PR」**:表達意願但不預設——讓維護者選
  「你來」或「我順手修了」。兩種結果都好。

## A.4 (選做)追加一行修正的 PR

如果 issue 得到正面回應(或你想直接附上修正),完整流程:

```bash
# 1. Fork:到 https://github.com/Canner/WrenAI 按 Fork(網頁操作,一次性)

# 2. 給既有 clone 加上你的 fork 作為 remote(不用重新 clone)
cd /home/kasm-user/Desktop/wrenai101/.wrenai-src
git remote add fork https://github.com/SnorlaxZeroTsai/WrenAI.git

# 3. 從最新 main 開 branch(命名:類型/簡述)
git fetch origin main && git checkout -b fix/guided-recall-flag origin/main

# 4. 改那一行:guided.md.tmpl 第 6 行
#    - 2. wren memory recall --nl "<keywords>"
#    + 2. wren memory recall -q "<keywords>"

# 5. 跑該模組的測試(CONTRIBUTING.md 的規矩;模板改動照理不會壞任何測試)
cd core/wren && uv sync --all-extras && uv run pytest tests/unit/test_ask_cli.py -q

# 6. Conventional commit(repo 規定;fix 類型會進 release notes)
git add core/wren/src/wren/ask_templates/guided.md.tmpl
git commit -m 'fix(wren): correct recall flag in guided ask template (--nl → -q)

The guided template instructed `wren memory recall --nl`, but recall
only accepts --query/-q; --nl belongs to `wren memory store`. Agents
following the guided flow verbatim hit an unknown-option error.

Fixes #<issue 編號>'

# 7. Push 到你的 fork,開 PR
git push fork fix/guided-recall-flag
#    然後到 GitHub 依提示開 PR:base = Canner/WrenAI main,
#    compare = 你的 branch。PR 描述可直接引用 issue:「Fixes #<編號>」
#    (合併時會自動關 issue)。
```

**教學點**:
- `Fixes #<編號>` 寫在 commit/PR body 是 GitHub 的魔法字串,合併即自動關聯
  關閉 issue——這是 issue 和 PR 的正式連結方式。
- 一行修正的 PR **不要**順手夾帶其他「我覺得也該改」的東西(比如你在第 1 章
  §1.2 還觀察到別的)——一 PR 一事,review 才快。其他發現另開 issue。
- PR 開出去後可能幾天沒動靜:正常。開源維護者是志工節奏,一週後禮貌
  ping 一次即可。

## A.5 心態備忘(第一次專用)

- **你不是在麻煩別人,是在送東西**。清楚的 bug report 是禮物,維護者靠
  這些活著。
- **被要求修改不是否定**。PR 被 comment「改成這樣」是流程的常態,
  照改、道謝、繼續。
- **被拒絕也有價值**。就算維護者說「這模板我們下版要整個換掉」,
  你也留下了一筆公開紀錄:你讀碼讀到能抓上游的 bug。這比 merge 徽章有用。
- 這個 bug 的完整發現過程在第 1 章 §1.2——從「引用原始碼時順手驗證每個
  flag」來的。**方法論本身就是貢獻的來源**:繼續用這套方法讀碼,
  issue 素材不會缺。
